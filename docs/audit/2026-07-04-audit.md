# rosnet — v1.0 Security / Hardening Audit (2026-07-04)

> Pre-1.0 audit of the full public surface (docs/api.md): `src/tensor.cyr` (110
> lines) + `src/linear.cyr` (135) line-by-line; `src/gpu.cyr` (2323) entry-point
> preconditions + buffer-fit paths. Method: manual derive-from-source pass over
> every exported symbol, checking (a) memory safety under stated preconditions,
> (b) failure-path behavior, (c) precondition enforceability. Findings below;
> **0 code changes required**.

## Verdict

**PASS — 0 reachable defects; the no-bounds-checks posture is audited as a
deliberate, documented contract, not an omission.**

## The substrate contract (the central audit question)

rosnet performs **no bounds or shape checks** on the CPU path. Cyrius has no
runtime bounds checking, so a caller passing a too-small buffer or wrong dims
gets silent heap corruption. For tarka's v1.0 audit the answer was fail-loud
`guard()`s on the public API; rosnet deliberately does **NOT** take that path:

- These ops are the innermost loops of every consumer (matmul is ~80% of a
  training step) — per-call dim/extent validation is unverifiable anyway
  (rosnet cannot know a pointer's true extent) and per-element checks would
  tax the exact hot path the library exists to provide.
- The contract is therefore **caller-guarantees**: pointers cover their stated
  row-major extents, dims are positive. It is stated in `docs/api.md`, the
  README, and the module headers. All six shipping consumers construct their
  buffers via `t_alloc` with the same dims they pass to the ops (checked:
  attn11 / rupantara / anukūlana call sites), so the contract is upheld in
  practice by construction.

## Per-surface findings

### tensor.cyr (storage + BLAS-1)

- **`t_alloc` is fail-loud** — `alloc()==0` (allocator cap / OOM) prints and
  `sys_exit(1)`, never returns 0 into pointer arithmetic. ✔
- `t_alloc` explicitly zero-fills even though `alloc` returns zeroed pages —
  redundant by design (documented: callers may rely on zeroing after reuse). ✔
- Degenerate `n <= 0`: every loop is `while (i < n)` → clean no-op; `t_alloc`
  with absurd/negative n lands in the fail-loud path via the allocator. ✔
- `f64_is_finite` checks the exponent bit-pattern directly — correct
  independent of the toolchain's f64-comparison NaN semantics (which were only
  fixed at cyrius 6.2.41). ✔
- `t_randn` → tyche `rng_normal` ships **unresolved** in the bundle by design;
  a consumer without `[deps.tyche]` fails at build (reachable-undef is a hard
  error on current cyrius), not at runtime. ✔

### linear.cyr (matmul + gradient)

- SIMD accumulators are 32-byte **function-local** buffers (`var acc[32]` =
  32 bytes local scope) — well inside the post-6.3.13 stack budget; SIMD-typed
  vars are never reassigned (the known miscompile is avoided, documented). ✔
- `linear_fwd` is bit-identical to the scalar form (axpy accumulation order
  preserved); `linear_bwd`'s dx uses 4-lane partial sums whose summation order
  differs from scalar within ~1e-16 — **documented honestly** at the fn, inside
  the grad-check tolerance. ✔
- The backward's accumulate-vs-write split (dW/db accumulate, dx writes) is
  documented at the module head and in api.md — the one API misuse trap
  (forgetting to zero dW between steps) produces *wrong gradients*, not memory
  corruption, and every consumer's train loop zeroes per step (grep-checked). ✔

### gpu.cyr (the `[lib.gpu]` profile)

- **Every device entry point guards before touching device memory**: `_gpu_init`
  ready-check → dims positive → `K % GPU_TK == 0` → `M*N ≤
  MABDA_MAX_DISPATCH_DIM` → **explicit BO-fit checks** (`M*K*8`, `K*N*8`,
  `M*N*8` ≤ `GPU_BO_MAX`) — so an oversized shape returns −1 (CPU fallback)
  instead of overrunning the 4 MB GTT maps. Verified on matmul/ln/gelu paths
  (lines 565–567, 635–636, 831, 947). ✔
- Failure paths (shader-compile cap, dispatch error) return −1 with the
  caller's output untouched; consumers all branch to the CPU op on non-0. ✔
- The shader cache stores compile-fail as −1 (no retry storm). ✔
- The GPU path's *device* trust boundary (command submission, VA layout) is
  **mabda's audit surface**, not rosnet's — rosnet passes fixed pool handles +
  VAs and never derives device addresses from user data. ✔

## Out of scope

- mabda device/DRM layer (own repo, own audit).
- tyche PRNG quality (statistical, not crypto — sigil owns crypto; documented
  in the README).
- The smoke `main()` (not in either dist bundle).

## Standing guidance for 1.x

Additions must keep the two invariants: **fail-loud allocation** (never return
a null tensor) and **guard-before-upload on every GPU entry**. Any future op
that parses external *data* (not caller pointers) — e.g. a quantized-dtype
loader — steps outside the caller-guarantees contract and must bounds-check
like tula/anukūlana's parsers do.
