# rosnet Audit Report — 2026-11-09

**Scope:** a P(-1) hardening, optimization and repair sweep (first-party
standards, *P(-1): Hardening*) over the whole repository outside vendored
`lib/`: `src/` (CPU kernels and the `[lib.gpu]` profile), `tests/`, `dist/`,
`scripts/`, CI and release workflows, and the documents. **Baseline:** 1.2.1
(commit `8b3ae88`, cyrius 6.7.18, tyche 1.2.2). **Result:** 1.2.2.

## Executive summary

One HIGH defect, in the GPU profile: `gpu_attn_core` had no head-dimension cap,
and its scores-kernel builder unrolls the head dimension into a function-local
`var spv[8192]` (8,192 bytes). At hd = 64 — GPT-2's head size — it wrote
11,172 bytes, 2,980 past the end of that stack buffer, before mabda's 256-id
cap could refuse the shader. The backward entry already carried the right cap
(hd ≤ 32, with a comment saying why); the forward never got it.

Three MEDIUM defects: the forward attention shader cache was keyed without hd,
so two head counts sharing (C, T) reused each other's kernel and returned a
wrong result with rc 0; a full shader cache (128 entries, though the arrays
hold 1024) leaked a compiled module per call and recompiled every call; and on
the CPU side, `t_alloc(0)` killed the process as "out of memory", while an
`n` just above 2^61 wrapped `8n` to a small size and the zero-fill ran off the
block.

The rest is LOW hardening (eleven GPU guard gaps, CI/release integrity, test
gaps), documentation that had drifted from the code (including a 10×
overstatement of conv throughput), and speed: `linear_fwd` 2.2–2.7×,
`linear_bwd` 1.6×, conv 3–13×, `t_scale` / `t_add_into` 7–9× — every one of
them bit-identical to 1.2.1 (ADR 0002).

## Method

- **Toolchain sweeps (6.7.18):** `cyrius vet`, `cyrius deny`,
  `cyrius doc --check` (17 undocumented public fns → 0), `cyrius coverage`
  (13/46 fns referenced; 7 public CPU fns untested → 0), `cyrius lint --strict`
  and `--strict-deferrals` on `src/` and `tests/`, `cyrius audit`,
  `cyrius deps --verify` / `--locked`.
- **Manual review** of every CPU kernel line by line; a delegated read-only
  review of `src/gpu.cyr` (shader-cache keys, host↔device copies, guards, error
  paths), with each reported finding re-checked against the code before it was
  accepted.
- **SPIR-V builder sweep:** every one of the 24 builders run on the host over
  its size parameters, recording bytes emitted and SPIR-V id bound, against the
  callers' `spv[8192]` and mabda's 256-id cap. This found the HIGH defect.
- **Golden dumps:** raw f64 bit patterns of every CPU op at fixed seeds —
  15,302 lines covering odd tails, rows of 128+ outputs, padding windows that
  miss the input, K = 0, every N mod 4, the no-bias / no-dx / no-db paths —
  byte-identical between 1.2.1 and 1.2.2, and between the 1.2.2 source at
  6.7.18 and the shipped 1.2.2 bundle compiled by cyrius 6.6.2 (five
  consumers' pin). An 18,167-line dump of every GPU builder's output, the Adam
  host scalars and the GELU constant is identical across 1.2.1 → 1.2.2 and
  across cyrius 6.6.19, 6.6.20, 6.7.9 and 6.7.18.
- **Mutation testing:** the golden gate killed kw-walked-upward, dW pre-summed
  and dropped-odd-tail mutants (one equivalent mutant — operands of a
  commutative add swapped — correctly survived). The new suite killed 7 of 7
  (odd-tail drop, `t_alloc(0)` regression, vector/scalar split moved, dW tail
  skipped, kw order, chunk-store edge, dW add order); the new fuzz harness
  killed 4 of 4 (incl. a reordered dx lane combine).
- **Consumer checks:** the six consumers' manifests (stdlib leaves, toolchain
  pins), and the shipped bundles compiled under those pins.
- **Benchmarks:** `scripts/bench-history.sh` (new) before and after, one
  session, median of three runs; 13 rows each.

## Findings

### HIGH — fixed

| # | Finding | Where | Fix |
|---|---|---|---|
| 1 | **Stack-buffer overflow in `gpu_attn_core`.** No hd cap; `_gpu_attn_scores` unrolls `while (d < hd)` into the caller's fn-local `spv[8192]` at 160 B per unit: 6,052 B at hd = 32, **11,172 B at hd = 64**, 21,412 B at hd = 128. mabda refuses such a shader (256-id cap) only after the build has written past the buffer. Reached by any consumer calling the forward attention with C / nh = 64 under `g_gpu_tc`. | `src/gpu.cyr` `gpu_attn_core` | `hd > 32` → -1 (CPU), as `gpu_attn_core_bwd` already did; also `T`, `nh` > 0 and `C % nh == 0` before `C / nh`. `tests/gpu_host.tcyr` pins every builder ≤ 8,192 B at its entry's guard limits, and the hd = 64 overrun itself. |

### MEDIUM — fixed

| # | Finding | Where | Fix |
|---|---|---|---|
| 2 | **Attention-forward cache key omitted hd.** `(kind << 56) \| (C << 28) \| (T << 14) \| k0`, while the scores and pv kernels bake hd, Ckv and scale. `gpu_attn_core(T=16, C=64, nh=8)` then `(…, nh=4)` share a key: the second runs the hd = 8 kernel, returns 0, and hands back a wrong `concat`. One attn11 run uses one nh, so it shows only in a process with several configurations. | `_gpu_get_attn` | Key `(kind << 56) \| (C << 34) \| (hd << 27) \| (T << 16) \| (k0 << 5)` (the abwd_t layout) with field checks; `C % nh == 0` makes Ckv = C and scale a function of hd. |
| 3 | **A full shader cache leaked and recompiled.** `_gpu_cache_put` stopped storing at 128 entries (the arrays hold 1024: a module-scope `var g[1024]` is 1024 slots). rosnet never releases a module, so each uncached call compiled and leaked one (a fresh GTT buffer object plus a 64 KiB-aligned slice of mabda's 2 GiB texture VA region), and compile failures stopped being cached — the "no retry storm" the 1.0 audit relied on. | `_gpu_cache_get` / `_gpu_cache_put` | Capacity 1024 (`_GPU_CACHE_CAP()`); a miss on a full cache answers -1, so every getter returns 0 without compiling and the op falls back to the CPU. | 4 | **`t_alloc` edge sizes.** `alloc(size <= 0)` returns 0, so `t_alloc(0)` — an empty tensor, a legitimate request — printed "out of memory, requested f64s: 0" to stdout and exited 1. For `n` just above 2^61, `n * 8` wrapped to a small positive size, `alloc` succeeded, and the zero-fill loop wrote 2^61 elements past the block. | `src/tensor.cyr` `t_alloc` | `n == 0` → a valid, distinct, zeroed one-slot block; `n < 0` or `n > 2^60 − 1` → "invalid size"; allocator refusal → "out of memory"; all on stderr, exit 1. Each path probed (exit codes and messages checked); `t_alloc(0)` is in the suite and the fuzz harness. |

## Observations — not changed, and why

- **GPU attention engages only for small heads.** At the guard limit hd = 32
  the scores kernel needs 302 SPIR-V ids and the dp kernel 290, over mabda's
  256-id cap, so those shapes compile-fail and fall back; forward attention
  runs on the device only for hd ≤ ~26. Tiling the hd loop would lift it — a
  GPU feature, not a repair.
- **Partial outputs on a GPU fallback** (finding 17) are documented rather
  than restructured: moving the readbacks after the last dispatch cannot be
  tested here (no device), and every consumer's fallback rewrites them.
- **GPU performance items** (from the review, untestable without a device):
  `gpu_head_bwd` re-uploads D_logits that nothing overwrote; `gpu_linear_bwd`
  copies dy twice; a dispatch failure is not sticky (a lost device re-uploads
  up to 12 MB per call before failing); some keys include values the kernel
  never bakes (wasted cache slots, not collisions).
- **The GPU bundle needs cyrius ≥ 6.6.19 in the consumer** (true since 1.1.3,
  when distlib began writing an `include "lib/mabda.cyr"` prelude into it).
  Under 6.6.2 mabda's `enum` lands after code ("unexpected enum"); 6.6.10–6.6.18
  stop at an undefined `MAP_SHARED`; 6.6.19, 6.6.20, 6.7.9 and 6.7.18 compile it
  and give identical builder output. The CPU bundle compiles and matches at
  6.6.2. attn11 (6.6.2, rosnet 1.1.2) is unaffected until it adopts ≥ 1.1.3.
- **`t_axpy` stays scalar.** `f64v_axpy` is fused on aarch64; packing it would
  give `t_axpy` the cross-target divergence `linear_fwd` already has.
- **`linear_bwd`'s dx stays a 4-lane chain**; a wider call would be more lanes,
  i.e. different bits. `t_sum` likewise.
- **`t_copy` / `t_zero` keep their 8-byte loops**: the stdlib `memcpy` /
  `memset` are byte loops (rep-movsb was removed for aarch64 alignment).
- **No AVX2.** `f64v256_*` would need a runtime CPU check (`lib/simd.cyr`, a
  new stdlib leaf in the bundle) and changes nothing about rounding; left for a
  throughput-blocked consumer.
- **`linear_bwd`'s db walks dy by column** (stride N). It is 0.1% of the op;
  a cache-friendly order needs a scratch row to keep its rounding order.
- **The f64v builtins have no scalar tail** (cyrius issue
  `2026-11-06-f64v-builtins-no-scalar-tail`, open): `n` rounds up to the lane
  count and they write past `dst`. Every rosnet call passes an even count and
  finishes an odd element in scalar code; the comments say so at each site.
- **`lib/agnosys.cyr`** was a scaffold-era orphan (2026-06-11) in `lib/` and
  `cyrius.lock`: in no 6.6.x or 6.7.x snapshot, used by nothing, and never
  pruned by `lib sync --full`. CLAUDE.md reserves `lib/` to the maintainer, who
  approved removing it; it was dropped the way cyrius documents
  (`rm lib/agnosys.cyr && cyrius deps`), leaving `lib/` exactly the 6.7.18
  snapshot plus tyche (114 locked files, `deps --verify` / `--locked` clean).
- **No-bounds-checks contract** — unchanged and still deliberate (the 1.0
  audit's analysis stands). Every fix here is about rosnet's *own* state:
  allocation sizes, GPU staging buffers, shader caches, build buffers.

## Downstream

No public signature changed, and every CPU result is bit-identical to 1.2.1;
`t_alloc(0)` now returns where it used to exit. The CPU sidecar is unchanged
(`alloc`, `string`, `fmt`, `syscalls`); the GPU sidecar adds `syscalls` and
`string`. All six consumers declare those leaves (manifests read 2026-11-09).
The GPU bundle no longer needs the consumer to define `puts`; a consumer that
does (attn11) keeps its own. Consumers' suites were not re-run.
